# A collection import is read by its header, and a printing is pinned only where Scryfall agrees

Someone moving to Meldweb Curator already keeps a collection somewhere else, and every app exports it differently: there is no standard format. [collection-import-formats.md](../research/collection-import-formats.md) is what a dozen of them write. Import takes any of those files, or a text list, and puts its cards into `collection.toml` (ADR-0023) as one edit.

- **Rust reads the file; the page only asks Scryfall.** `chip-decklist`'s `collection_import` decides whose export a file is, what each row names and where it goes, as `chip-decklist` decides what a deck line is. The page fetches what the reader asks for and hands the answers back, so no TypeScript decides what a row means.
- **A file is known by its header, never by column order.** ManaBox has added columns three times since 2023, Archidekt and the TCGplayer app let the user pick them, and Moxfield takes them in any order. Each app is a profile: the headers that mark it, and which of its columns are the quantity, name, Scryfall ID, set, number, finish and place. A file no profile marks is read by the commonest column names, and one with no header is a text list, read as Archidekt text is.
- **A row names its card by the best key its file has.** A Scryfall ID is trusted. A set and collector number is a claim: Dragon Shield, TCGplayer and MTGGoldfish write codes of their own, and a code that happens to be Scryfall's for another set would name another card. So a printing is pinned only when Scryfall's card at that set and number has the row's name, a double-faced card's front face included. Otherwise the row goes in by name, and the import lists it with why. Deckbox's codes and numbers are reshaped beyond that check (`DDC-49` written `49`), so only its Scryfall ID is read.
- **A binder is a place.** ManaBox's binders and decks, Dragon Shield's folders and Sorted's lists become places, declared when the collection lacks them. Rows with no place go where the user says: unsorted, a place, or a new one. A ManaBox *list* is cards wanted or for trade, not owned, so its rows are skipped and counted.
- **Add or replace.** Add puts the copies on the lines already holding the card alike in that place, as quick add does. Replace makes each place the import fills hold exactly what it brings, keeping the lines that already held those cards where they are: importing an unchanged export again leaves the file byte for byte as it was, and a changed one is a commit that says what changed since, in the collection's own changelog.
- **Nothing is dropped without a word.** A row whose quantity or finish is no word this knows is left out and listed, never guessed. A file that counts copies in columns this does not read (`Reg Qty`, `Foil Qty`) is refused rather than read as one copy a row. Columns the collection has no key for, condition, language and price, are counted and named before the import is confirmed.
- **One edit.** The whole import is one change to the text: undo takes it back, and the save is one commit.

## Considered Options

- **A parser per app, by column position.** Rejected. Positions move, and a reader that matched a ManaBox export from 2023 would read 2026's `Added` column as something else.
- **Trust every set and number.** Rejected. It pins the wrong card wherever an app's codes are its own, silently, which is worse than a card named by name with a note saying why.
- **TCGplayer product ids.** Deferred. Scryfall's `/cards/collection` does not take them, and `/cards/tcgplayer/:id` is a request per card. Set and number, checked, covers TCGplayer's exports bar its own set codes.
- **Delver Lens `.dlens` backups.** Rejected. Its card ids resolve only through a database inside Delver's app package. Its CSV presets imitate other apps and are read as those.
- **Condition and language as line keys now.** Deferred, as in ADR-0023. Every export carries them, so an import is where the pressure for them will come from; until a key exists, the import says what it left behind.
