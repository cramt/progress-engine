# Curator answers card facts from its own copy of Scryfall's bulk data

Supersedes the recommendation of [docs/research/scryfall-in-the-browser.md](../research/scryfall-in-the-browser.md) (#107), which was to call Scryfall's API for every card fact and keep no card data in the browser. Settled in [#141](https://github.com/cramt/progress-engine/pull/141). [ADR-0031](0031-gauntlet-and-curator-keep-one-copy-of-scryfall.md) makes the copy Gauntlet's too: its format, builder and lookups are `chip_scryfall::copy`, and where this record says the copy is Curator's alone, that one wins.

Every view of a deck or the collection asks Scryfall something: the deck view's printings and prices, the printing picker and the all-printings grid, search, quick add, a collection import, a scan. Through the API each is a request on a queue that allows two a second, so opening a large deck, stepping through printings or importing a collection waits on Scryfall's rate limit, and works only online. Each browser now keeps its own copy of Scryfall's bulk data and answers all of these from it, in a worker.

- **The browser downloads Scryfall's own files.** The first visit streams Default Cards (79 MB gzipped) and Oracle Tags (6 MB) from `data.scryfall.io`, which sends `access-control-allow-origin: *`, through `DecompressionStream` into `meldweb-wasm` a few megabytes at a time. Nothing is republished or proxied: each browser fetches from Scryfall, as it would fetch the API, which keeps clear of the terms the research doc quotes.
- **The copy is Scryfall's card objects, split in two.** What a card says is kept once for every printing that says it alike, and what each printing says of itself beside it; sets, and a printing's look (language, rarity, frame, flags, games, finishes), are kept once and named. Joining the halves gives back the object Scryfall wrote, which a test holds against every printing of the bulk file. Pictures are not card facts: they stay on Scryfall's CDN, and the copy keeps only the version their URLs end in.
- **It is kept in origin-private storage, gzipped, in one of two slots, and a meta file written last names the slot.** A new copy goes in the other slot, so a copy cut short by a closed tab, or by a full disk, is never read and never costs the old one. Every hour an open tab looks whether its copy is a day old, and if so asks `/bulk-data` whether Scryfall wrote a newer file, making a new copy in the background while the old one answers. Prices are the day's, as the API's are. Copies are made under a Web Lock, so a second tab waits for the first's copy instead of downloading its own, and a file the wasm cannot read is remembered by its `updated_at`, so a page load does not download 85 MB again to fail again.
- **The copy answers only when it is ready.** Until then, when it throws, and when it does not answer within ten seconds, every lookup goes to the API and its cache as it did before the copy existed (`viaCopy`). A page load does not wait for a stored copy to be read back. So the first visit works while the copy downloads, and a browser that cannot keep one (no worker, no origin-private storage) loses nothing.
- **What the copy does not find, Scryfall is asked for.** The copy can be a day behind, and Scryfall matches names more loosely than the copy's exact match (`Juzam Djinn` finds Juzám Djinn, `Ice` finds Fire // Ice). So a lookup asks the API for only the cards the copy missed, and an empty search, autocomplete or list of printings asks the API whole. A card neither knows costs a request each time it is asked, as it did before the copy.
- **Search refuses what it cannot read, and then Scryfall answers.** The copy searches with `chip-scryfall`'s `parse_printing`: one printing per card, sorted by name, extras left out, oracle tags expanded to their ancestors as Scryfall's `otag:` is. A query it refuses (`year:`, `usd<`, a misspelt keyword) goes to Scryfall's `/cards/search`, which may know it and shows its own warnings when it does not.
- **A card named by name gets the printing the default `[printings]` rules rank first** ([ADR-0026](0026-which-printing-comes-first-is-a-ranked-list-of-printing-queries.md)), not Scryfall's pick: the copy has every printing, so it ranks them the way the editor does.
- **The kept text is read without JSON where it can be.** A first line of JSON holds the sets, looks, tags and formats; then a line per card and a line per printing, their fields between tabs. A card's own JSON is not read until something asks for that card, and the worker reads the rest a few hundred at a time once the copy is ready, between the page's questions. A search has to read every card, so until that is done searches go to the API rather than hold the worker for seconds. Reading the copy as one JSON document through facet took 18-19 s in wasm under Node; this takes 2.7-3.4 s on the same machine, and reading every card for search 8.5-14 s more, in the background, in slices of at most a fifth of a second. In Chromium a reload has the copy answering 4.5 s after the page starts.

## Considered Options

- **The API for everything** (the research doc's recommendation). Rejected now that it has been lived with: a deck of a hundred cards in several views, a 1,000-row collection import and a scan session each queue behind a 2-a-second limit, and nothing works offline. The cost the research doc weighed against a copy, a cold start, is paid once per browser and in the background, while the API answers.
- **Ship a reduced index from the site** (`decks/index.jsonl`, or a build of the copy). Rejected for the reason the research doc gives: it is republishing Scryfall's data, and it needs a scheduled job to stay fresh. The browser downloading Scryfall's file needs neither.
- **Oracle Cards instead of Default Cards.** Rejected: one printing per card cannot answer the printing picker, a deck's `set/num`, prices or a scan's Scryfall id.
- **A binary format for the kept copy** (msgpack, postcard). Rejected on measurement: msgpack decoded 10% faster than JSON, because the cost is the number of values read through facet, not their encoding. `facet-postcard` needs facet 0.50.
- **Blocking lookups until a stored copy is read back.** Rejected: it held every page load for the seconds the read takes, when the API and its cache could answer meanwhile.
